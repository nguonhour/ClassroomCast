# Final academic report outline

**Version:** 0.1 · **Prepared:** 9 November 2026 · **Status:** Proposed review draft; no teacher approval or product test execution claimed.

## 1. Report status

This is an outline for later completion, not a final report of implemented work. Retain planning proposals separately from observed implementation and results.

## 2. Chapter structure

| Chapter | Required content | Evidence source |
|---|---|---|
| 1 Introduction | Context, validated problem, objectives, scope and limitations | Teacher interviews, approved proposal |
| 2 Background and related technology | Local media, signaling, SFU, policy integration; justified reuse | Reviewed primary technical sources for selected versions |
| 3 Requirements and method | Roles, MoSCoW, use cases, decisions, Scrum and course application | Requirements register and meeting records |
| 4 Analysis and design | Architecture, workflows, logical data/API/security/infrastructure | Versioned design and decisions |
| 5 Implementation | Actual components/configuration and deviations from design | Repository/build/version; do not fill before implementation |
| 6 Testing and evaluation | Methods, environment, raw results, defects and limitations | Executed test catalogue and pilot evidence |
| 7 Project management | Planned versus actual scope/time/effort/risk; Scrum learning | Board, effort records, reviews and retrospectives |
| 8 Conclusion and future work | Achieved outcomes, unresolved limitations and next work | Accepted evidence, not planned feature counts |
| Appendices | RTM, decision log, deployment/user guides, test records | Linked controlled artifacts |

## 3. Writing controls

Do not fabricate literature, screenshots, benchmarks, surveys or references. Cite actual sources reviewed and describe limitations. Separate future work from unfulfilled required scope; an unaccepted Must gap cannot simply be relabeled an enhancement.
